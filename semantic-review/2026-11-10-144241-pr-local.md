# Metapath DWPC link prediction for Compound-treats-Disease

The change adds a supervised link-prediction pipeline on Hetionet that scores every (Compound, Disease) pair for a "treats" edge. `src/features.py` builds DWPC walk counts for 11 metapaths plus 5 log-degree features as dense 1552 x 137 matrices. `src/train.py` splits the 755 CtD edges 70/10/20 and computes features from a graph that keeps only the training CtD edges. It trains a degree-product baseline, logistic regression and XGBoost on 10:1 sampled negatives, selects on validation AUPRC, and evaluates once on test. It then retrains on all labels and writes the top 20 compounds per disease, each with a metapath "evidence" column. The current run selects LR (C=0.01) with test AUROC 0.968, AUPRC 0.193, compound-centric MRR 0.588 and disease-centric MRR 0.249.

No val/test leakage into features or evaluation was found. The diagonal removal is exact, hop orientations are correct, the ranking metrics are correct, and the test set is never used for selection.

Watch for: training positives' CtD degree features count their own edge, a train/eval mismatch that measurably hurts test performance (confirmed); the evidence column cites metapaths that lower the final model's score (confirmed); hyperparameter selection on 76 validation positives is noisy and disagrees with test ordering (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

Leakage control works as described. Every feature matrix is computed from `Graph.with_edges` over the training CtD pairs, so val/test edges never enter any walk, degree weight, degree feature or asinh scale. For the six metapaths with CtD as the first or last hop, removing the diagonal of the C x C (or D x D) sub-chain is numerically identical to deleting the pair's own CtD edge while keeping degrees.

The remaining self-reference sits in the degree channel. `deg_CtD_Compound` and `deg_CtD_Disease` for a training positive include its own edge. No training positive therefore has compound degree 0, while 36–40% of val/test positives do. This makes test metrics pessimistic, not optimistic. The same mismatch carries into the final retrain.

Negative sampling and evaluation follow the filtered link-prediction setting, and the filtered MRR/Hits@K with half-weighted ties is correct in both orientations. Two small inconsistencies remain. Ranking candidates include training negatives while AUROC/AUPRC exclude them. The negative pool is also cleaned using held-out labels.

Model selection never touches test, but 76 validation positives can't order the grid points reliably.

Final predictions exclude all known treats and palliates pairs. The evidence column ignores the model, so it lists metapaths with negative weights. For sparse metapaths it reduces to "a path exists".

1. **Own-edge CtD degree for training positives** (confirmed, medium): `deg_CtD_*` counts the pair's own edge for training positives only (features.py:199-200). Use `log1p(deg - 1)` for positive rows in the training frame, or compute training-positive features out-of-fold. Apply the same fix in the final retrain.
2. **Own-edge degree inside label-hop DWPC weights** (likely, low): the CtD hop's `deg^-0.4` weight also counts the training positive's own edge. An out-of-fold feature build fixes this together with issue 1.
3. **Evidence ignores the model's sign** (confirmed, medium): CtDaGaD has a negative coefficient in the final LR (−0.115) yet appears as evidence in 1303 of 2740 predictions. Rank evidence by per-feature contribution (`coef_ * scaled x` for LR, `pred_contribs=True` for XGBoost) and list only positive contributors.
4. **95th-percentile threshold is a no-op for sparse metapaths** (confirmed, low): CrCtD, CiPCiCtD, CtDrD, CuGdD and CdGuD are nonzero for under 5% of unknown pairs, so any nonzero value qualifies. Use the contribution rule from issue 3, or compute percentiles over nonzero values only.
5. **Noisy hyperparameter selection on 76 val positives** (confirmed, medium): validation and test order the XGBoost grid differently. Select by k-fold CV over the train+val labels, and report test metrics with a bootstrap CI or across several split seeds.
6. **Ranking and AUC use different negative sets** (confirmed, low): `ranking_metrics` keeps training negatives as candidates (train.py:99), but `evaluate` drops them from AUROC/AUPRC (train.py:206). Use one candidate mask for both, or document the difference.
7. **Training negatives filtered with held-out labels** (confirmed, low): `unknown = ~known` (train.py:201) removes val/test positives from the negative pool, which a real deployment couldn't do (about 6 collisions expected). Document this as the filtered convention, or sample from pairs that are neither training positives nor palliates.
8. **CbGpPWpGaD counts gene-revisiting walks** (confirmed, low): walks c→g→pw→g→d are kept, so the feature partly duplicates CbGaD scaled by pathway count. If path semantics are intended, remove the diagonal of the G x G `GpPW·PWpG` block.

### Label-edge masking and the diagonal trick

`FeatureBuilder.matrices` (features.py:178) rebuilds CtD from the pairs it receives. It gets the 528 training pairs at train.py:199 and all 755 pairs for the final model at train.py:270. The per-hop degree weights, the degree features and the asinh scale (`arr.mean()` over all 212,624 pairs, features.py:192) all read that substituted graph. The scale uses no labels beyond the training edges.

Label-last metapaths compute `offdiag(W_1…W_{k-1}) · W_CtD` (features.py:188), and label-first metapaths compute `W_CtD · offdiag(W_2…W_k)` (features.py:190). For a training positive (c, d), a walk uses edge (c, d) only when the node next to the label hop equals the far endpoint. Zeroing the diagonal is therefore both necessary and sufficient, and walks that revisit c earlier but end on another c' never touch (c, d).

```
label-last:   c ──b── g ──b── c' ──t── d     c' = c  → removed (uses own edge)
label-first:  c ──t── d' ──a── g ──a── d     d' = d  → removed (uses own edge)
```

A brute-force check deleted (c, d) from the weighted CtD matrix with degrees kept and recomputed the chain for 76 training positives per metapath. It matched the code to 1.1e-16 on all six label-hop metapaths. The removal changes 99% of training positives for CbGbCtD, 76% for CiPCiCtD, 95% for CcSEcCtD and 100% for CtDaGaD. It changes none for CrCtD and CtDrD, because CrC and DrD have no self-loops.

Every configured hop has the correct orientation. DaG, DdG and DuG are transposed when walked G→D. PCiC is transposed on C→PC and kept as-is on PC→C. GiG, CrC and DrD come out of `m + m.T` (features.py:94) symmetric with zero diagonal. Because GiG has no self-loops, walks only differ from paths in CbGpPWpGaD, where c→g→pw→g→d is counted. This partly explains why that feature is nonzero for 80% of unknown pairs.

### Own-edge degree bias in training positives

Degree features are read straight from the train-label graph (features.py:199-200). A training positive's `deg_CtD_Compound` and `deg_CtD_Disease` therefore include the edge being predicted. Val/test positives and all negatives never get that +1. No training positive has a compound with zero training CtD edges, against 36% of val positives and 40% of test positives. With the own edge subtracted, 41% of training positives would have zero, so the +1 accounts for the whole gap. LR's largest coefficient is on `deg_CtD_Compound` (0.92), so the model leans on a feature whose distribution shifts between training and evaluation.

A scratch experiment subtracted the own edge from both CtD degree features, for training-positive rows only. Validation still picks LR C=0.01, but test AUPRC rises from 0.193 to 0.210 and disease MRR from 0.249 to 0.267. For C ≥ 0.1, test AUPRC goes from 0.14–0.16 to 0.214. XGBoost test AUPRC improves at every grid point (0.133→0.149 at 200 trees, depth 3) and test AUROC rises from about 0.94 to 0.976, even though its validation AUPRC drops. All 755 positives in the final retrain carry the same +1, so the bias also shapes the written predictions.

The CtD hop's degree weight inside label-hop DWPCs counts the own edge too: the disease's degree in label-last metapaths and the compound's in label-first ones (likely a smaller effect, not quantified). Building training-positive features out-of-fold fixes both: split the training labels into k folds and compute each fold's features from a graph without that fold's edges.

The random edge split puts roughly 40% of test positives on compounds with no training indication. The headline metrics therefore mix warm-start and cold-start pairs, and reporting the two groups separately would make results like the degree baseline's 0.024 test AUPRC easier to read.

### Negative pools and the filtered ranking

`known` (train.py:179) is every CtD pair in any split plus the 390 CpD-only pairs, and training negatives come from its complement (train.py:201-203). Excluding val/test positives from the negative pool is the usual filtered convention, and only about 6 collisions out of 5,280 would be expected otherwise. It still uses held-out labels, and the report should say so.

AUROC/AUPRC use `eval_neg = unknown & ~train_neg` (train.py:206). Ranking candidates are `~known[r]` (train.py:99), which keeps training negatives. The ranking code matches `scipy.stats.rankdata(method="average")` on the same candidate set exactly, for both the row call and the `scores.T, pc, pr, known.T` disease-centric call. When training negatives are filtered out, LR test Hits@10 by disease rises from 0.397 to 0.431. The other metrics barely change. Either definition is defensible, but both metric families should use the same one. Neither model memorizes its sampled negatives: their mean within-disease score percentile is 0.495–0.502, against 0.498 for evaluation negatives. The final model's training negatives can therefore stay in the prediction pool.

### Validation-based selection with 76 positives

Each grid point is scored on validation (train.py:220-226), the winner is scored on test once (train.py:227), and `best_name` uses validation only (train.py:236). Test is never consulted. The weak point is size. Validation AUPRC orders the XGBoost grid as 200/3 > 500/3 > 200/5 > 500/5, while test orders it 200/3 > 200/5 > 500/3 > 500/5. LR's validation AUPRC spans only 0.088–0.122 across C, a spread 76 positives probably can't resolve (likely). The degree-fix experiment shows the fragility: it improved XGBoost on test and lowered it on validation. K-fold CV over the 604 train+val labels would stabilize selection without touching the test protocol.

### Evidence column in predictions

`write_predictions` draws candidates only from `unknown[:, c]`, so known treats and palliates pairs never appear. The evidence logic (train.py:290-305) compares each pair's DWPC value against all unknown pairs and never consults the model. In the final LR, CtDaGaD (−0.115), CuGdD (−0.045) and CbGiGaD (−0.012) have negative coefficients. CtDaGaD is still the second most common evidence entry, appearing in 1303 of 2740 rows, so the explanation cites a feature that lowers the score. The 0.95 threshold also has no effect on sparse features. CiPCiCtD (0.6% nonzero), CrCtD (0.9%), CtDrD (1.2%), CuGdD (2.3%) and CdGuD (2.8%) pass it whenever they are nonzero, so only dense features such as CbGpPWpGaD are actually filtered. Ranking evidence by contribution fixes both problems: use `coef_ * scaler.transform(x)` for LR and `Booster.predict(..., pred_contribs=True)` for XGBoost, keeping only positive terms.
